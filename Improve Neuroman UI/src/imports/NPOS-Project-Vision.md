# Neurofunk Production OS (NPOS)

## Project Vision & Architecture

---

## Core Design Principle
**Whenever there is a choice between more information and better workflow, always choose the better workflow.**

**NPOS is a production operating system, not an encyclopedia.**

The purpose of this project is not to collect information. The purpose is to help produce better music, faster, more consistently, and with better decision-making.

Every document, framework, checklist, template, workflow, and AI interaction should support that goal.

---

## Vision
Neurofunk Production OS (NPOS) is not an ebook, course, or collection of notes.

It is a long-term production operating system designed for modern Neurofunk and Drum & Bass production.

The primary objective is not to create the biggest documentation. The primary objective is to build a system that is used during every production session.

NPOS should function simultaneously as:

- Production mentor
- Knowledge base
- Workflow system
- Project management system
- Reference analysis framework
- Sound design knowledge system
- AI production assistant

Everything inside the project must be designed around practical production.

---

## Long-Term Goal
The project must be designed to grow for years.

Every new:

- PDF
- Article
- Tutorial
- Preset Pack
- Track Analysis
- Interview
- Personal Note
- Experiment

must be integrated into the existing system instead of creating another isolated document.

NPOS is a living knowledge system.

## Core Philosophy
The entire project is built around several rules.

### 1. Decision System
This project is not an encyclopedia. It is a decision system.

Every document should help answer: “What should I do next?” instead of “How much can I read about this?”

### 2. Sound Design and Mixing
Sound design and mixing are never treated as separate disciplines. Every sound is evaluated inside the mix from the very beginning.

### 3. Stay in MIDI
Keep sounds editable as long as possible. Render only when rendering provides a clear advantage.

### 4. One Layer = One Function
Every layer should have exactly one purpose.

Examples:
- Sub
- Body
- Movement
- Noise
- Stereo
- Air
- Texture
- FX

Avoid layers with multiple conflicting purposes.

### 5. Producers are Philosophies
The project never attempts to copy producers. Instead it extracts production philosophy.

Examples:
- Audio
- Redpill
- Aggressor Bunx
- Mefjus
- Noisia
- Black Sun Empire
- Neonlight
- Burr Oak

The objective is to understand why they make decisions.

### 6. Transform Knowledge
Never copy information directly. Every external source must be transformed into:

- Measured facts
- Estimated observations
- Hypotheses
- Production principles
- Lessons learned

## Project Architecture
The system consists of several layers.

### Framework
Contains reusable systems.

Examples:
- Decision Trees
- Workflows
- Checklists
- Templates
- Production Frameworks
- Session Systems

Frameworks define how production decisions are made.

### Knowledge
Contains engineering knowledge.

Examples:
- Bass Engineering
- Drum Engineering
- Arrangement
- Composition
- Sound Design
- Automation
- FX
- Mixing
- Mastering
- Low End
- Stereo

Knowledge should never become isolated documentation. Everything should link together.

### Case Studies
Every analysed track follows exactly the same structure.

Metadata:
- Track
- Artist
- Version
- Producer
- Label
- Year
- BPM
- Key
- Length

Analysis:
- Structure
- Energy
- Bass
- Drums
- Stereo
- Dynamics
- FX
- Automation
- Mix
- Master

Then:
- Production Decisions
- Workflow to Recreate
- Lessons Learned
- Confidence

### Producer Knowledge
Never create biographies. Each producer contains only:

- Production Philosophy
- Sound Design
- Arrangement
- Mixing
- Mastering
- Common Patterns
- Unique Ideas
- What To Learn

### Preset Knowledge
The objective is not to archive presets. The objective is to extract production principles.

Each preset should become:
- Oscillator Strategy
- Routing Strategy
- Filter Strategy
- Modulation Strategy
- FX Strategy
- Macro Design
- Engineering Decisions
- Production Philosophy
- Lessons Learned

The project focuses on recurring patterns rather than individual parameter values.

### Knowledge Objects
Knowledge should exist only once.

Example:

FM Synthesis

→ links to
- Serum Presets
- Phase Plant Presets
- Audio
- Redpill
- Aggressor Bunx
- Bass Engineering
- Case Studies

Duplicate information should never exist. Everything should be connected through internal links.

For example:

→ Extract

- Common Distortion Chains

## AI Philosophy
The AI is not a search engine. The AI is a production mentor.

For every question it should:
1. Identify the production stage.
2. Select the appropriate workflow.
3. Select the relevant checklist.
4. Select the decision framework.
5. Recommend the next concrete production step.

The AI should avoid unnecessary theory whenever practical guidance is available.
